ZeroBroker - Microservices Architecture Notes

Architecture Preference:
The project follows a microservices architecture.


High Level Structure:

Frontend
    |
    |
Ingress / API Gateway
    |
    |
Backend Microservices
    |
    ├── Auth Service
    ├── Home Service
    ├── Buy Service
    ├── Rent Service
    └── Search Service



Why Microservices:

- Each service has a separate responsibility.
- Each service can be deployed independently.
- Each service can scale independently.
- Failures are isolated between services.
- Separate CI/CD pipelines can be created.
- Kubernetes deployments and services are managed separately.



Kubernetes Structure:

Each microservice will have:

1. Deployment

   - Defines container image.
   - Controls replicas.
   - Manages pod lifecycle.


2. Service

   - Provides stable networking.
   - Routes traffic to pods.


3. ConfigMap / Secret

   - Stores configuration and environment variables.
